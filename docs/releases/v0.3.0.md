# ModelPilot v0.3.0

Release notes draft — local release preparation only. No tag or GitHub Release has been created
by V03-008; v0.2.0 remains the published stable version pending release approval and CI.

## Highlights

- Provider health tracking scoped to each provider/model pair
- Deterministic CLOSED / OPEN / HALF_OPEN circuit breaker
- Configurable counted-failure threshold (default 3) and cooldown (default 60 seconds)
- Automatic isolation of OPEN providers before automatic routing scores are computed
- Request-driven cooldown recovery with single-flight HALF_OPEN probes within one process
- SQLite-persisted health state that survives restart
- Health-aware structured route explanations, including excluded candidates without scores
- Read-only `GET /v1/health/providers`, separate from service liveness at `GET /health`
- Dashboard health monitoring with failure counts, cooldown deadlines, probe state and timestamps

## Reliability

Repeated counted failures temporarily remove unhealthy provider/model candidates from auto routing.
Eligible alternatives continue to serve requests; when every circuit is unavailable the existing
503 contract is preserved. Timeout, connection_error, rate_limit, provider_error, invalid_response,
and unknown_error count; authentication_error remains visible but does not count toward the circuit.
Metrics and health persistence failures are isolated from successful inference responses.
Health read failures fail open for inference, whereas the Health API reports an explicit 503.

## Recovery

At the inclusive cooldown boundary a candidate becomes eligible for a recovery probe. One request
can hold that provider/model's probe lease in the current process; concurrent requests skip it and
use alternatives rather than waiting. Success closes the circuit and clears consecutive failures;
a counted probe failure opens it again with a new cooldown. Leases are released on completion,
exceptions, persistence failures and cancellation. No background health checks are performed.

## Compatibility

V0.2 confidence-blended scoring, usage normalization, estimated costs, rolling metrics and existing
OpenAI-compatible core API fields are preserved. Auto explanations use routing version v0.3 and
retain selected-versus-served semantics. Explicit-model requests bypass auto health filtering and
do not generate artificial auto explanations.

SQLite schema remains version 3. Fresh databases initialize at v3; v1/v2 databases upgrade while
preserving attempts, prices and decisions. Old V0.2 explanation JSON without health fields remains
readable. Back up the stopped application's database before upgrading; rollback to V0.2 requires
restoring the pre-upgrade backup because there is no down-migration.

## Limitations

Probe coordination is **single-process only**, not a distributed circuit breaker. Multiple workers
or replicas do not share leases. Health reads are snapshots, not admission guarantees; health
storage retains the latest snapshot, not an event history. The supported deployment is a single
local process using SQLite.

There are no manual reset/open/close/probe controls, multi-process coordination, background health
workers, authentication, multi-user/multi-tenant isolation, billing/payment, streaming, benchmark
engine, ML/AI Router, Redis, PostgreSQL, or additional providers. Quality remains a configured
baseline; this release makes no live benchmark or performance improvement claims.

Metrics and health storage do not persist prompts, completions, API keys or authorization headers.
Route and health explanations expose operational metadata, not credentials.
